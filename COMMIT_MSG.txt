THE BATCH-0 DESIGN SAID <column role= source=/> AND THE CODE REVERSED IT.
<column> is a parser-level construct shared with xlsx2csv and built to map
~100 columns in json2csv; putting six fixed roles through it would mean
touching the parser's column handling for three executors to express what
six keys already express. diff sets the precedent with match.N.*. With
map.<role> parameters the parser change for this executor is the whitelist
and nothing else. The spec is corrected in place rather than quietly
followed.

THE OBJECTS ARE NEVER COPIED. A tar member's name is independent of where
its bytes are read from, so the Transarch rename happens while streaming
straight out of the landing zone. The script staged every object into
%TEMP% before calling tar.exe, which at the documented 20 GB CS ceiling is
20 GB written and read to produce nothing. emitObjects materialises the
renamed copies when they are actually wanted; it is off by default, because
a TAR submission delivers only the tar and the md5.

FlatCsvReader is line-based, so a record split by a bare newline cannot be
rejoined by it. A row whose field count disagrees with the header is
refused WITH THE FIX NAMED (dequote, csvsql) rather than parsed into
something plausible.

Refusals that exist because the alternative is worse than failing: a mapped
object_id that does not ascend from 1 is refused, NOT renumbered, since
replacing an id the feed chose breaks every downstream reference; an
ambiguous name match under recurse fails naming both paths, because picking
one would archive a plausible wrong document under a right-looking name; a
CSV-supplied path that escapes objectsDir is refused, not clamped. Nothing
is written until every cheap check has run, so a submission that will be
rejected fails before producing a 20 GB archive.

GATE 0. Answered and implemented: OID width derives from the object count
for every feed; mime_type is the dotted extension, so the pre-flight is a
comparison and not a media-type lookup; the executor owns all five
artifacts from the source CSV; transmissionDate is required and never
defaults to today, because a default would rename the submission on a retry
the next day, which spec section 2 forbids. Five questions stay open, each
with a conservative default, and compression refuses anything but none with
a message that names the question.
