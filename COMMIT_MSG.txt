json2csv batch 1: the core, and eight mutations to prove the suites bite

Eleven classes in com.legalarchive.orchestrator.json2csv, free of Spring and
free of Jackson, compiled with javac --release 8 and exercised in the sandbox.
203 assertions, all green.

Nothing outside the new package is touched. There is no call site yet, so this
batch cannot change the behaviour of any existing feed; the executor arrives
in batch 2.

THE SANDBOX CHECK IS STRONGER THAN THE PROJECT BUILD

The pom sets maven.compiler.source and target to 1.8, which does not check the
API surface. --release 8 does. Verified on the day rather than assumed:
List.of fails to compile under the flag. mvn clean package on your machine
remains the only final proof, because Maven Central is unreachable from here.

ABSENT AND MISMATCH

Implementing the spec's "absent is data, non-scalar is a wrong mapping" made
the rule wider than the spec had it, and better. ABSENT is a key that is not
there, an index past the end of an array, or an explicit null: the document
does not have it, so the cell is empty and counted. MISMATCH is a key applied
to something that is not an object, an index applied to something that is not
an array, or a leaf that turned out to be an object or an array: the document
is not shaped the way the path assumes, so onNonScalar decides, and it
defaults to stopping.

Folding the two together is the expensive mistake here. A mapping typo would
deliver an empty column for the whole feed and look exactly like a customer
who happens to have no value. The mutation that folds them is caught by
thirteen assertions.

A value that will not read as a Number, or as a date under any mask, takes the
same route. That makes onNonScalar a slightly wrong name for what it now does.
The name is kept because it is already in the committed spec, and the designer
label in batch 3 will say what it means rather than repeat what it is called.

THE DATE MASKS ARE MEASURED, NOT ARGUED

The spec argues that trying YYYY/MM/DD, YYYYMMDD and YYYY-MM-DD in order is
safe because no value parses under two of them. An argument is not a
measurement, so the suite renders every day of a full year in all three forms
- 1095 strings - and asserts each parses under exactly one mask. Overlaps
found: zero. That test is the guard on the warning that a fourth mask is not
automatically safe.

STRICT is exercised for real: 2026-02-30, 2026-13-01, 20260230 and 2026-02-29
are refused, and 2024-02-29 is accepted.

THE TRANSLATOR IS EXTRACTED, NOT RETYPED

The suite contains no copy of fmtToJavaPattern. It reads InternalSteps.java at
build time and lifts the method and its JT_PASSTHROUGH constant verbatim, so
"YYYYMMDD becomes uuuuMMdd" is a fact about the shipped translator and not
about a copy that could drift. The core reaches it through a one-method
MaskTranslator seam, because InternalSteps is Spring-coupled and this package
has to compile with the JDK alone.

THE SUITES WERE SEEN TO FAIL FIRST

Eight mutations of the real source, each compiled and run: the [] refusal
removed from the validator; [] resolved as [0] instead of refused; dates
parsed SMART instead of STRICT; Serial restarting on every row; MISMATCH
folded into ABSENT; Number going through double instead of BigDecimal; the
output-mask probe removed; and describe() leaking the value into the finding.
Every one was caught by named assertions, listed in the spec.

The first run found a defect in the SUITE and not in the core: under the first
mutation it died on probs.get(0) of an empty list and stopped reporting
everything after it, which is the opposite of what MappingValidator does on
purpose. The runner now turns an unexpected throw into a failure, and that
mutation is caught by eight assertions instead of a stack trace.

VERIFIED / NOT VERIFIED

Verified: the package compiles with javac --release 8 against the JDK alone,
so brace balance and imports are proved by the compiler rather than by a
counter; 203 assertions green; eight mutations caught; that no file outside
the new package is touched.

Not verified: mvn clean package, for the reason above. Everything the executor
does with files - reading, the wildcard mask, CsvWriter, the counters end to
end - is batch 2. The suite is not committed, as the elar suites are not; say
the word and it goes in with a runner.
