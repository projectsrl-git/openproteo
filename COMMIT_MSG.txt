XML viewer: make the header backgrounds actually stand out

Reported after the table view landed: the element title bands and the table
headers were barely distinguishable from the body, particularly in the light
theme where both were nearly white.

Element headers now sit on a solid tinted band with a 4px accent bar down the
left edge, so the start of every element is unmistakable even where several
are stacked one after another, and the tag has a slightly larger type size.
Table headers are darker still, uppercase and letter-spaced, with a 2px accent
underline separating them from the rows.

The colours were chosen by computing WCAG relative-luminance ratios rather
than by eye. Element header against the body is now 1.89 in dark and 1.54 in
light, where the previous values were around 1.05 - which is why it read as no
separation at all. Table header against the body is 2.37 and 1.80. The header
text was checked against its own new background and sits between 6.9 and 9.7,
so the separation was not bought by making the labels harder to read.

These four surfaces use literal hex rather than theme variables because no
existing variable was strong enough for the job; everything else in the view
still comes from variables, and both stylesheets were re-checked so that no
variable is referenced that does not resolve.

Verified: node --check passes on viewer.js and on the standalone page, both
still with zero literal newline/CR escape sequences and no external
references, and the contrast ratios above were computed rather than assumed.

NOT verified: how it looks on your screen, which is the only thing that
actually settles this. Reload xml_viewer.html on the same file and switch the
theme once.
