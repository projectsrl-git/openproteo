unarchive: batch 2, zip reader, limits, staging and commit, manifest

Gate 0 Q4-Q12 confirmed with the recommended defaults. UnarchiveRun now
extracts end to end against real files; still unregistered, no call site.

New in package unarchive: ZipCentralDirectory (our own central directory
reading, ZIP64 included, for raw names and external attributes),
ZipArchiveReader (ZipFile for streams, our records for names/types/
encryption/method, cross-checked on count and every name; four-rule name
charset with IBM850 fallback; symlinks recognised; CRC-32 and size checked
per entry), FileMask (copy of json2csv's), Budget (limits on bytes
written), UnarchiveRun (config refusals, sweep, selection, prechecks over
every archive before the first extraction, .part staging, one rename to
commit, replace with rollback, manifest with SHA-256, Stop).

Spec corrected by tests: per-entry compression ratio dropped for gzip
(decompressor read-ahead makes it meaningless, measured); encryption and
method checks moved before ZipFile is opened (JDK 21 refuses such zips in
the constructor, Java 8 does not); tar magic with a bad checksum is a
corrupted tar, not unrecognised (I30).

232 (batch 1, re-run). Zips from Info-ZIP, jar, python and python
streaming byte-identical to their source tree; real ZIP64; every hostile
zip and tar refused by its own rule with outputDir left empty. Mutations:
batch 2 35 (33 caught, 2 equivalent, argued in the spec), batch 1 34 all
caught. An earlier mutation run was discarded after the suites' temp dirs
filled the disk; suites now clean up and everything was re-run.
