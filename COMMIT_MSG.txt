Log report next to Operations, and index the output data declared on the steps

Log report now sits next to Operations in the topbar of every page, with the same filled style, and the
duplicate small button on the dashboard toolbar was removed.

The index was reporting zero outputs and the runs grid showed no output data. The cause was in the
indexer: output variables are declared in two places and it only read one. Operations reads both the
outputData.<var> parameters on each step, which is what the designer's OUTPUT DATA box writes, and the
workflow-level outputData block. upsertRun used only the workflow-level map, which is empty for every
feed that declares its outputs on the step, so in practice nothing was indexed. It now collects the
declarations from the steps first and lets the workflow-level block override them, matching exactly what
Operations displays. The index is rebuilt from the files, so a Reindex or a restart is needed after
deploying before the outputs appear.

Note on the details column, which is not addressed here: it shows the audit payload, because that is
what the audit line carries. The step log itself lives in separate per-step files under the run directory
and is not part of the audit trail.
