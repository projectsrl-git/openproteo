Log report Batch 2a: rolling window, run and output-data indexing, facets

Decisions taken on the spec's open items: the rolling window is ninety days and the refresh interval
stays at ten seconds. The feed and log directories are already configurable and were left untouched.

This batch changes one design decision of .claude/LOG_REPORT.md. Section 2.2 excluded the run snapshots
as a search source, but the audit line only carries exitCode, attempts and reason: the output data shown
in Operations and in the run history is not in the audit trail at all, it lives in the run's vars matched
against the outputData declarations on the workflow. Indexing runs is therefore required, and the note
committed with this change supersedes that section.

The rolling window is openproteo.logreport.window-days, defaulting to ninety; entries and runs older than
the cutoff are not loaded, while the per-feed sequence pointer still advances past them so old lines are
read once and never re-examined. Setting it to zero disables the window.

Two tables are added: run_entry with the run status, trigger, who started it, start and end, message and
the step counts, and run_output with the declared output variables, their descriptions and the values
that run produced. Run files cannot be tailed like the append-only audit because they are rewritten while
the run progresses, so the indexer stamps each file with its size and modification time, re-reads only
what changed and replaces that run's rows, which keeps a run that moves from RUNNING to SUCCESS from
being duplicated.

GET /api/logs/runs returns those runs with filters on feed, source, target, status, user and time plus
free text, paginated, each row carrying its output data. The free text also searches inside the output
values, labels and variable names, so looking for the run that produced a given row count works. The
outputs for a whole page are fetched in one additional query rather than one per run. GET /api/logs/facets
returns the values for the filter controls: feeds, sources and targets from the registry, events,
severities, run statuses, output variable names and users from the index. /api/logs/status now also
reports the window and the number of indexed runs and outputs.

Still to come: the /logs page itself, the timeline, the metric cards, export and RBAC gating.
