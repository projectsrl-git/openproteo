Promote Operations to every topbar, and build a standalone artifact alongside the WAR

Operations is the view people actually live in, and it was a small button buried in the dashboard
toolbar. It is now a filled button in the topbar of every page, overview itself excluded, so it is one
click away from wherever you are. It uses a dedicated .btn.ops class rather than .btn.primary: that
class already styles other buttons across the application, such as Validate and save, and redefining it
would have silently restyled all of them.

The build now produces two artifacts instead of one. target/openproteo.war is the plain WAR you deploy
on the external Tomcat and is unchanged, byte for byte; target/openproteo-standalone.war is executable
with an embedded Tomcat and runs with java -jar. This works because the Spring Boot repackage now runs
with a classifier, so it writes a second file and never touches the one being deployed, and because
spring-boot-starter-tomcat is already declared provided, which makes Boot place it in
WEB-INF/lib-provided: on the classpath when the artifact is run directly, ignored when a container
deploys it. The standalone artifact is not attached to the Maven install, so nothing changes in the
repository.

One honest limitation: with war packaging Maven cannot emit a file with a .jar extension. The standalone
artifact is a .war that behaves exactly like a fat jar, and renaming it to .jar also works since the JVM
only reads the manifest. A genuine jar artifact would require a second Maven module, which is a larger
change. The usual Boot switches apply when running it, for example --server.port and the OpenProteo base
directory.
