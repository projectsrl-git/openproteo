Log report: lazy peek at the step log from the grid

The details column shows the audit payload, which is all the audit line carries. The step log, the
script output itself, lives in per-step files under the run directory and is deliberately not indexed: it
is one to three orders of magnitude larger than the audit and indexing it would have turned a disposable
in-memory index into something needing a persistent store and a real search engine.

Every event row that has both a run and a step now carries a step log chip in its details cell. Clicking
it expands a panel under the row with the last three hundred lines, fetched on demand for that row alone
and reusing the endpoint the run page already uses; clicking again collapses it. Nothing is pre-fetched,
cached or indexed, the cost is one request per peek, and the log files remain the only copy of that data.

Failures degrade politely: a missing or unreadable log shows a message with the HTTP status inside the
panel rather than breaking the row, and an empty file says so explicitly. Rows without a run or a step
get no chip because there is no step log to show.

Docs: .claude/2026-08-04-step-log-lazy-peek.md and CLAUDE.md.

Verify: logs.html passes node --check with zero literal \n or \r and no unsafe Thymeleaf, and no backend
change was needed since the endpoint is the one already used by the run page. The interaction could not
be exercised in the chat sandbox: after deploying, open the log report on Events and click the chip on a
row that has a step.
