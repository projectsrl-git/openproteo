Add scripts/build_openproteo.sh: build (+ commit and push) on bash, for TEST and PROD

The Windows .bat covers the chat patch workflow; this is the bash equivalent for the test and
production boxes, stamping the version into the WAR in exactly the same way.

    ./scripts/build_openproteo.sh          build, commit -F COMMIT_MSG.txt, push (asks first)
    ./scripts/build_openproteo.sh -b       build only - the normal case on TEST / PROD
    ./scripts/build_openproteo.sh -n       build and commit, do not push
    ./scripts/build_openproteo.sh -m "..." use this message instead of COMMIT_MSG.txt
    ./scripts/build_openproteo.sh -y       skip the confirmation prompt

The commit hash only exists after the commit, so when committing the script builds twice: the first
build merely proves the code compiles, so nothing broken is ever committed, and the second stamps the
real identity into the WAR with -Dgit.commit=<short HEAD> and
-Dbuild.number=<git rev-list --count HEAD>, which Maven filters into build-info.properties and the
topbar shows. With -b the hash is already known, so a single stamped build runs -- which is why
build-only is the right mode on test and production, where you pull and rebuild rather than commit.

Guards: set -euo pipefail; git and mvn must be on PATH; it must run inside the repository (it cd's to
the top level) and pom.xml must exist; COMMIT_MSG.txt must be non-empty unless -m or -b is used; patch
files are excluded from the commit exactly as the .bat does; the WAR is checked after each build; the
staged diffstat is shown and confirmed before committing; commit and push are skipped when nothing is
staged. At the end it prints the stamped build-info.properties and warns if a placeholder was not
substituted -- that single check would have caught the ${git.commit} delimiter bug at once.

Docs: .claude/2026-07-28-build-script-bash.md and CLAUDE.md.

Verify: checked with bash -n, then exercised end to end against a stubbed mvn in throwaway git
repositories -- build-only (one stamped build), commit without push (two builds, commit created, patch
files kept out, only sources committed since target/ and *.war are gitignored, confirmed with
git check-ignore), nothing to commit (commit and push skipped, stamped build still runs), missing
COMMIT_MSG.txt (clean error), an unsubstituted placeholder (warning fired) and -h. Re-run inside a
clone with the patch applied: the file lands executable (mode 100755) and reports the real progressive.
