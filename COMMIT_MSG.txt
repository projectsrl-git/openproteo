Mask: the street type word moves from the code into the pool values

Implements .claude/MASK_ADDRESS_PREFIX.md section 10. No new parameter, no
designer change, nothing for the author to decide: the street pool carries
the complete street and the dropdown that already exists selects it, which
is how the executor behaved originally.

MaskGenerators.address() loses its "Via " constant and returns street plus
number. The two draws are untouched and in the same order - that is the
whole constraint. streets_it.txt gains "Via " on all 60 values;
streets_international.txt gains its own type word on all 177, in each
country's word order: Oakwood Street, Bahnhofstrasse, Rue Voltaire, Calle
Serrano, Amstelstraat, Aarestrasse. Four Dutch entries - Damrak, Rokin, Spui,
Overtoom - are complete streets on their own and correctly carry no suffix.

The same method's empty-pool fallback "Roma" becomes "Via Roma". That branch
is reached only when the pool file is missing or unreadable, and without this
it would have started emitting "Roma 47". Found by reading the line, not by
reviewing the diff.

Nothing in a value can tell the executor whether the type word is present:
Damrak is a complete Dutch street and Garibaldi is not a street name at all,
so a heuristic would fire on the legitimate Dutch entries and pass a broken
Italian pool. There is therefore no guard, only visibility: runMask logs the
street pool in effect on every run with its size and first value. Both file
headers and USAGE.md say to keep the type word when replacing a pool.

Batch 1's own prose is inverted one commit later - both file headers, the
USAGE.md paragraph and the CLAUDE.md lines. That is part of the change.

  clean clone of 3921bd5 and from the patched tree, both run over 3010
  values with the default pools across address, city, fullName, company and
  customerDescription: identical SHA-256
  dd104f43c4d6f5b3cf3bfab6742fd115d20335dfe72c1673fd822538746da036 and the
  same sample "Via Petrarca 47". That is the same digest measured before
  batch 1 at f437d43, so the default output has not moved once in this whole
  piece of work. The empty-pool fallback matches too: "Via Roma 142" both
  sides.
- Why it holds: pool.length is unchanged at 60, so nextInt(pool.length)
  draws the same index from the same stream position and the type word rides
  on the value instead of being concatenated after it. The counter-case was
  measured earlier - a pool one entry LONGER moves 1962 of 2000 addresses.
  Content may change freely; length may not.
- 828 assertions green, javac --release 8, against the real MaskEngine,
  MaskPools and MaskGenerators, including two new invariants: every
  streets_it value starts with "Via ", and no streets_international value
  does.
- The log line was COMPILED AND RUN, not just written. InternalSteps needs
  the Spring tree, so the added statements are lifted verbatim from the real
  file - asserted character-identical - into a stub compiled against the real
  MaskPools, and executed for the Italian pool, the international pool and a
  missing file.
- Charset: every character in all four pool files is inside both ISO-8859-1
  and windows-1252, eszett included, so a masked value survives a Latin-1
  sink downstream.
