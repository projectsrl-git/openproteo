Raise the transition limit per workflow with the variable maxTransitions

orchestrator.max-transitions (500) stopped a check of 50 packages at the
50th and could be raised only by restarting the server. The engine now
reads the run variable maxTransitions - of the workflow, or global - at
every entry into a run: a whole number above the configured limit raises
it, up to 100000; a lower one leaves the configured limit; anything else
stops the run before its next node, saying so. The audit records the
limit used (TRANSITION_LIMIT), and the "Exceeded the limit" message now
says how to raise it. Without the variable nothing changes.

The objunpack templates' descriptions say how to use it; they carry no
empty maxTransitions variable, which would hide a global one. USAGE
(Loops) and spec .claude/MAX_TRANSITIONS_VARIABLE.md.

Verified on Linux (JDK): Temurin 1.8.0_432 and OpenJDK 21.0.12 - the
decision method lifted and run (21 cases, mutations), the walker on a
template with a lowered limit, the engine by differential compilation.
Verified on Windows: nothing.
Not verified: the engine's loop at run time, AIX.
