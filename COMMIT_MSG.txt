elarxml: trace every document to its INDX, and hide files while in flight

Two changes asked for together, both about what someone downstream can see.

THE PER-DOCUMENT TRACE

logDocuments, on by default: one line per document naming the INDX it went
into, the document id from input.doc_id_reference and the content file name,
then a total when the INDX is delivered together with the PULL it is paired
with.

ELAR validates an INDX in full and rejects it in full, so the first question
after a rejection is always which documents were in that file. Answering it
used to mean reopening the INDX and parsing it.

Only those two identifiers are logged, never a field value. That is the same
line the pre-scan and the findings file already draw: a document id and a file
name identify a document, whereas the metadata beside them identifies a
customer. A feed of two hundred thousand documents produces two hundred
thousand lines, so logDocuments=false exists for a feed where that is more
than the step log should carry.

THE IN-FLIGHT NAME CHANGES ITS TOKEN, NOT JUST ITS SUFFIX

An INDX is written as x.I_PART.C152100.part and a PULL as
x.P_PART.C152100.part, taking their deliverable names only once complete.

The .part suffix on its own was not enough, and that is the point of the
change. Everything downstream that looks for deliverable files matches on the
TOKEN rather than the extension: the reference PowerShell scripts default to
*INDX*, and elarcheck's filePattern defaults to *INDX* as well. A half-written
x.INDX.C152100.part is a match for both. Replacing the token means a file in
flight cannot be picked up by a permissive pattern whatever it matches on,
which is a stronger guarantee than asking every consumer to be careful.

The last occurrence of the token is replaced, so a family whose own name
contained it keeps it. A name with no token at all still gets the suffix: the
protection degrades rather than disappearing.

VERIFIED
- 33 assertions. The naming: both substitutions, the last-occurrence rule, a
  name without the token, and one with an extension after it.
- The behaviour rather than the arithmetic: the output directory is watched
  WHILE a run is in progress, and every file seen in flight is checked to
  match neither *INDX* nor *PULL* while carrying the part marker. Asserting
  the final names only would have proved nothing about the window this change
  exists to close. Then that the delivered names are untouched and nothing is
  left as .part.
- The trace: all six documents traced to the INDX that received them, every id
  and content file name present, the total and the PULL pairing reported, no
  metadata value anywhere in the log, and the switch silencing it without
  changing what the run delivers.
- 110 designer assertions, up from 108, covering the new field. All seven elar
  suites and both panel suites unchanged, scans clean.

NOT VERIFIED
- mvn clean package: Maven Central is unreachable from the chat sandbox, so
  the build on the target machine remains the only final proof. The elar
  package compiles and runs standalone in full; the two lines added to
  runElarXml cannot be compiled here, since the engine package needs Spring
  from the internal Nexus.
