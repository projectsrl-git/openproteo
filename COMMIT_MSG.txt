json2csv, batch 0: specification, and the sandbox decides the shape

Specification committed at .claude/JSON_TO_CSV_EXECUTOR.md, self-contained. No
code in this commit.

The executor reads the JSON files matching a wildcard mask in a directory and
writes ONE flat CSV whose shape is the feed's dataschema, filling its columns
from JSON attribute paths chosen against a JSON schema. Nested objects and
arrays are flattened: the row count follows the cardinality of the innermost
MAPPED array, and everything outside it repeats on each row it covers.

NO GATE 0 ON NEXUS

jackson-databind already arrives with spring-boot-starter-web, and
ApiController, DataSourceStore and InternalSteps already use ObjectMapper. No
new dependency, no question to ask.

THE CONSTRAINT THAT SHAPES THE DESIGN

The elar package is free of Spring and compiles standalone with javac
--release 8. That is what has let every suite in that subsystem run the real
code against real files in the sandbox, and it is what caught the .done rename
defect, the value-edge breaks and the split start tag.

Maven Central is not reachable from the sandbox - verified,
repo.maven.apache.org answers 403. A core that imported com.fasterxml.jackson
could not be compiled here at all, and the flattening rules, which are the
part of this executor that is genuinely easy to get wrong, would ship
unexercised.

So the split is at the only place where it is free. The tree is Map, List,
BigDecimal, String, Boolean and null - precisely what
ObjectMapper.readValue(file, Object.class) already returns, and precisely what
InternalSteps.readSchemaColumnNames already reads the dataschema as today. The
core is pure over that tree and runs here against trees built by hand. Jackson
appears in exactly one class, JsonDocumentReader, whose whole body is the read
call, the USE_BIG_DECIMAL_FOR_FLOATS setting and the size guard. That class is
the only part that cannot be exercised in the sandbox, and the delivery says
so.

--release 8, not -source 8 -target 8: only the former checks the API surface.

NOTHING NEW WHERE SOMETHING EXISTS

CsvWriter already does UTF-8, CRLF, RFC-4180 quoting and split-by-rows /
split-by-MB for sql, csvsql and xlsx2csv, so requirement 7 is a wiring job and
the output conventions are byte-identical by construction. columnsSchema is
reused as the parameter name because the sql executor already calls the path
to a dataschema JSON exactly that.

THE DATE FORMAT IS A MASK

recordBusinessDateFormat carries forms like YYYY/MM/DD, where DD is
day-of-month and not day-of-year. Feeding it to DateTimeFormatter.ofPattern is
the defect recorded in CLAUDE.md under "the date MASK is not a java.time
pattern", which silently broke businessDateNotBefore for the life of the
product. Date columns go through InternalSteps.fmtToJavaPattern, both for
output and for input masks. Reimplementing it here would reintroduce the bug.

THE FLATTENING RULE

S is the set of array prefixes of the mapped paths that have a src. An array
nobody reads from does not multiply rows, which is what requirement 4 means by
"ovviamente se tali elementi sono mappati". If S is a chain, rows come from
nested iteration over it; outer values repeat because reading at the current
index is what repeating means.

Sibling arrays - accounts[] and notes[], neither containing the other - are
refused by default. The product is silent: a run that should write 400 rows
writes 4000, each value repeated, with nothing in the output saying which
repetitions are real. CROSS is available per step, in the open. The check is
static, on the mapping, so it fires before a file is opened.

An empty or absent array yields ONE row and not none, recursively at every
level: a LEFT JOIN rather than an INNER one. The default must not lose a
document in silence.

DECISIONS WORTH ARGUING WITH AT THE GATE

ObjectName is a column TYPE and not a parameter naming a column - the same
dropdown as Serial, the other column whose value does not come from the JSON.
Serial restarts neither per input file nor per split part, because the parts
are one delivery and a Serial that restarted would give two rows the same
number. <column> is reused rather than a hundred params: ColumnSel gains four
optional fields, written only when non-empty, so an xlsx2csv step round-trips
byte-identically - asserted in batch 2 by reading and rewriting every workflow
XML in the repo and comparing SHA-256, before anything else is touched.

GATE 0 - SIX QUESTIONS THAT GATE BATCH 1

All about the data, none answerable from here: the largest JSON file and how
many per run, which decides tree against streaming; whether one file is one
document or holds an array of them; whether two independent arrays ever need
mapping together; what dates look like inside the JSON; whether MIMEType wants
.json or application/json, and of which file; and whether the dataschema's
nullable:false should be enforced, which is specified and off.

VERIFIED / NOT VERIFIED

Verified: Jackson is on the classpath; Maven Central is unreachable (403);
CsvWriter's split contract; that readSchemaColumnNames reads both dataschema
dialects; that fmtToJavaPattern exists and what it translates; that ColumnSel
is shared with xlsx2csv and carries only src and as today; the six
