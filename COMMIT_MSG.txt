bash runner, process-tree kill, pwsh on Linux: batch 2 spec

Spec only, no code. No Java, template, JS, pom.xml, README.md change;
USAGE.md goes with the code; no new runtime parameter in this commit.

.claude/LINUX_AND_GUI_CONFIG.md section 8, written on fifteen
measurements (8.2) taken with a real Java 8 runtime (Temurin 1.8.0_432)
and JDK 21, PowerShell 7.4.6 for Linux, and the real StepExecutor and
RunControl compiled by the Java 8 javac:

- destroyForcibly() leaves every child of a bash script alive, the
  foreground one included, and execute() returns 5 s late. Launching
  under setsid and killing the session plus the descendants leaves
  none. What still escapes is measured and declared.
- Stop does not stop a fan-out today, on any platform: RunControl holds
  one process per run and concurrent items overwrite it. Three items,
  Stop: one dies, two run to the end. Fix proposed in this batch.
- A non-ASCII parameter passed by ProcessBuilder becomes "???" when the
  service has no UTF-8 locale, as argument and as environment variable.
  So bash receives its parameters as OP_<name> variables built by an
  all-ASCII bootstrap, as PowerShell receives base64.
- The PowerShell bootstrap works unchanged under pwsh on Linux; its
  error stream does not (CLIXML and ANSI escapes) without
  -OutputFormat Text and TERM=dumb.
- The bundled application.properties sets powershell-exe, so no
  platform default can apply until that line is removed.
- Windows tree kill is not solved: Java 8 holds a HANDLE, not a pid.
  The code delivery will include a measurement kit to run there.
