Operations drill grid: sort by the two date columns, newest run first by default

The feed list under the rollup was rendered in backend order, so the feeds that ran most recently were
not necessarily at the top.

The grid now opens sorted by LAST RUN descending, and both date columns are sortable. "Last run" and
"Last success" are clickable headers with an indicator: the active column shows an accent-coloured
up/down triangle and the other a faint sort glyph. Clicking the active column toggles ascending and
descending; clicking the other switches to it starting from descending, which is what you almost always
want for dates.

The comparator compares the timestamps as text, which is chronological for the yyyy-MM-dd HH:mm:ss
format the backend sends, tie-breaks on the feed id so equal timestamps keep a stable and predictable
order, and always sends missing values last in both directions: a feed that never ran, or never
succeeded, must not push real data off the top when sorting ascending. The sort is applied to the
filtered list immediately before drillDisplayed is set, so "CSV (displayed)" and Copy export in exactly
the order shown on screen. Only the drill grid is affected; the live-executions table is untouched.

Docs: .claude/2026-07-30-drill-sort-by-date.md and CLAUDE.md.

Verify: the real sort state, comparator and click handler were extracted from the template and executed
in Node against the feeds from a production screenshot plus a never-succeeded and a never-run feed --
the default puts the newest run first, the toggle reverses it, sorting by last success pushes the
never-succeeded feed last, the never-run feed stays last in every mode, and each click triggers exactly
one re-render. overview.html passes node --check with no literal \n or \r and no unsafe Thymeleaf.
