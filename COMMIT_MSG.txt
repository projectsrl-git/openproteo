feed schema index 1.1: a skip now names the path it looked at

Reported from the field: every feed skipped as "no dataschema" while
both schema files are plainly present in the designer's Workflow files
panel. The upload location was never the doubt - AssetStore.scopeDir
returns FeedLayout.feedDir, so the tool looks in the right kind of place
- but the message could not distinguish "the file is missing" from "the
directory is missing", and those two have opposite remedies.

The defect is therefore the message, and it is the one that cost the
round trip. "no dataschema" reads as a statement about the estate when
it is almost always a statement about -BaseDir. Three changes, all
diagnostic:

Every skip names the exact path it looked for, so the answer is in the
output instead of in a second conversation.

A missing feed DIRECTORY is its own cause, with its own counter
feed_dir_missing, and its note points at both -BaseDir and the
workflow's own baseDir attribute. A workflow carrying baseDir overrides
the command line exactly as FeedLayout does, which is the single most
likely way for a whole estate to be skipped with nothing saying which
value won.

The run states both directories it was pointed at before it reads the
first feed, so the first lines of output already answer "what was this
run looking at".

Same principle as ElarConfig replacing a production NPE with a message
naming the bad family, the properties file and the families it does
contain.

156 assertions, 16 mutations all caught, the last two being the reverts
of this change: a skip note that stops naming its path, and a missing
directory folded back into the missing-schema case.

NOT VERIFIED, unchanged from batch 1: Windows PowerShell 5.1 (the
sandbox has 7.4.6 for Linux; the dialect is six scans with positive
controls) and the real estate.
