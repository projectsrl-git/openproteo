Business date not in the future: on for every feed, opt-out per step

Requested: apply the check to all feeds, including ones created and run long
before it existed. The batch that introduced it deliberately did the opposite
- preselected for new steps only - and flagged the choice as one to be made
rather than assumed; this makes it.

The checks list could not deliver this. checks="..." is a positive list, so a
workflow whose XML already carries one can never pick up a new id, and
rewriting every definition to add one is not a deploy anybody should have to
run. The check is therefore governed by an opt-out parameter instead: it is on
unless a step carries businessDateNotFuture=false. Absent, empty, or any other
value means on; only an explicit false turns it off, so no stray value can
disable it by accident.

The designer renders it as its own chip ahead of the other checks, ticked by
default: unticking writes businessDateNotFuture=false on that step, ticking
removes the parameter again. It was removed from CHECK_IDS and from the list
seeded for a new validate step, so the two spellings cannot disagree with each
other; a step whose XML still lists the id among its checks is simply already
consistent with the new rule and needs no edit.

The net effect is that the check applies everywhere from the next run, and
stays de-selectable one step at a time - which is what was asked for
originally and is still true.

Verified with 13 assertions compiled with -source 8. Every shape of existing
feed is reached: a step with no params at all, one carrying only the other
business-date settings, one predating the check entirely. The opt-out works
and is forgiving about case and surrounding whitespace, an empty value means
on because that is what ticking the box writes, and neither true nor an
unrelated value can turn it off. And the assertion that carries the argument:
a step holding a typical existing checks list would NOT have been selected by
the old positive-list rule, while the new rule does reach it.

node --check passes on designer.html with zero literal newline/CR escape
sequences.

NOT verified: mvn clean package, and a real run. Worth watching the first
scheduled night after this: any feed whose source genuinely carries
forward-dated business dates will now fail where it used to pass, and the fix
for those is Business date max on that step rather than unticking the check.
