csvsql: expose newlinesInValues in the designer, log the count

The engine already honoured the parameter: runCsvSql has read newlinesInValues
and published ${newlinesSanitized} since the 2026-07-24 extraction patch,
through the same SqlSupport.exportResultSet(..., nlMode) as the sql executor,
so the three options are identical by construction. What was missing was the
way in. designer.html rendered the dropdown only in the 'sql' branch, and the
Variables page could not fill the gap because it lists only params already
present on a step - so the parameter was reachable only by hand-editing the
workflow XML, while static/USAGE.md already promised it for csvsql.

The csvsql panel gains the dropdown (keep / space / strip, default keep) and
runCsvSql gains the "normalised line breaks inside N value(s)" line that
runSql already logged when the counter is > 0. Wording differs from the sql
panel on purpose - sql normalises what a database returns, csvsql what an
input CSV carries - while the values stay identical, so the neutral
PARAM_OPTIONS entry on the Variables page remains correct for both. No
parser/writer/DTO/model change: newlinesInValues is a generic <param> that
already round-trips, and it is not a required field, so clientValidate is
untouched. Default stays keep: no feed changes output on deploy.

The scope limit was measured, not deduced. Driving the exact CSVREAD staging
statement from runCsvSql into the verbatim exportResultSet on real H2 2.1.214:
a break inside a QUOTED input field is reassembled by CSVREAD and then
collapsed (newlinesSanitized=1, one physical line); a break at the EDGES of a
value is already gone because trim defaults true and String.trim() eats CR/LF;
a BARE unquoted break has already shredded the record into two malformed rows
inside CSVREAD before the exporter sees anything, and is not repairable here -
that stays with dequote or the extraction upstream. The designer hint says so.

Verified: the end-to-end H2 run above; the new fragment rendered in Node for
absent / "" / keep / space / strip / SPACE / garbage (exactly one 'selected'
each, tags balanced); designer.html inline scripts pass node --check with zero
literal backslash-n or backslash-r and zero unsafe [[ or [(; InternalSteps
braces balance at 0 ignoring strings and comments, and the added statement
needs no new import. Each scan was first run against a deliberately broken
copy and did flag the injected defect, so the clean results mean something.

NOT verified: mvn clean package - Maven is unreachable from the chat sandbox,
so the build on the working copy is the final proof.
