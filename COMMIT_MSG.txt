Log report Batches 5 and 6: CSV export, reindex from the UI, cold scan outside the window

Batch 5. GET /api/logs/export streams the whole filtered set as CSV with StreamingResponseBody, paging
through the index rather than materialising it so a large export costs a bounded amount of memory. A
UTF-8 BOM is written so Excel opens the file correctly and there is a hard stop at one million rows. The
columns match the grid, and the run export flattens the output data as name=value pairs.

RBAC Phase 1 is not on main yet, so this endpoint is ungated: anyone who can reach the application can
export the whole audit trail. That is deliberate and temporary. The property
openproteo.logreport.export-enabled set to false turns the endpoint off with a 403 until role scoping
lands, and the endpoint should be gated as soon as authentication is merged. The page gains a CSV button
and a Reindex button, the latter confirming first and then reporting the rebuild time.

Batch 6. The rolling window and the incremental byte-offset tail already shipped with Batch 2a; what was
missing is the fallback for a query reaching back before the window, which memory cannot answer.
LogIndexer.coldScan now reads the audit files directly, restricted to the feeds in the filter and capped
at twenty thousand rows, without writing anything into the index, and the search routes to it
automatically and re-applies the same predicates in Java before sorting and paging.

A cold query that names no feed, source or target is refused with an explanatory message rather than
scanning all one hundred and forty-four files, which is exactly what the design forbids. Responses carry
coldScan and truncated flags and the page states that the rows were read from the files, so it is always
clear which path answered.

Verify: the CSV escaper was compiled and executed -- a delimiter or a quote forces quoting, inner quotes
are doubled, CR and LF collapse to a space so a value can never break the row, and null and empty both
give an empty field. Brace balance was checked with the string and comment aware counter and logs.html
passes node --check with zero literal \n or \r and no unsafe Thymeleaf. The cold scan could not be
exercised end to end in the chat sandbox with no H2 and no real audit files: after deploying, query a
range older than ninety days for a single feed and check that the footer reports the file path.
