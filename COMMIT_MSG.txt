Platform diagnostics panel: /platform, read-only (batch 1)

Batch 1 of the Linux / GUI-configuration programme. Gate 1 answered,
all five as recommended.

New page /platform (dashboard nav, after Docs) over GET /api/platform:
OS and JVM identity incl. sun.jnu.encoding and the effective default
charset, user.dir beside ten resolved paths (exists, kind, writable),
SunMSCAPI presence, each configured interpreter resolved WITHOUT being
executed, and a case-sensitivity probe of defaultBaseDir. Read-only:
nothing is created, a missing directory is a finding. No new runtime
parameter, no dependency, no executor touched.

platform/PlatformProbe is JDK-only and holds every decision;
web/PlatformController only chooses which values are described. Probe
again is POST /api/platform/case-probe: the probe writes one temp file,
is cached for the JVM's life and refuses more than one write per 60 s.
An empty path is "not set", never resolved; a relative interpreter path
is UNDETERMINED; a not-determined probe is never cached.

tools/scan_platform_whitelist.js (exit 1) enforces the whitelist:
property and environment reads by literal name within the list, fixed
AppProperties getters, one createFile and one delete, nothing that
creates a directory or starts a process.

USAGE.md: "Platform diagnostics". Spec section 7 marked delivered, 7.13
records what the implementation decided. README.md not touched.
