unarchive: batch R, nested archives (opt-in)

nested=extract extracts archives found inside an archive, in place
(inner.zip becomes inner/), then removes them, down to nestedDepth (3);
deeper ones are kept with a warning. Nested archives are selected by
name with the step's pattern, never by content, so .docx/.xlsx/.jar
(which are zips) are never opened. Everything happens in the outer
archive's staging folder: any failure at any depth fails the outer
archive and nothing of it is committed. Size limits count the whole
tree; a gzip stream's ratio counts only that stream's bytes. On Linux a
nested archive's links must stay inside its own folder. Manifest rows
name nested files as inner.zip!entry. New output ${nestedExtracted}.

Designer select and depth, PARAM_OPTIONS, USAGE.md "Archives inside
archives".

Verified: nested suite 30 with fixtures from real tools; all earlier
suites unchanged (Windows 232, batch 2 199, Linux 140, links 77,
non-root 7); wiring 101; panel 130; guide 52; 22 mutations caught. A
panel check that read the inline script source (and so could not fail)
was found by a surviving mutation and fixed.
