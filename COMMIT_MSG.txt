Spec: headless artifact and command-line control channel (H0)

Spec only, no code. .claude/HEADLESS.md (r4) designs a third artifact,
openproteo-headless.war, with no web server in it, and a CLI that drives
the single engine through a file-based control directory: inbox, work,
outbox. The user recorded for a CLI action is the OS owner of the request
file, so access control becomes the server's own logon (two-factor at
UBS) plus the ACL of the inbox.

Decided with the author: one engine plus a file channel rather than a JVM
per command (the engine, the run-id counter and the audit chain tail are
all per-JVM state); reads go through the channel too; instance settings
are saved in <workflowsDir>/openproteo-instance.json and written from the
Platform page; personal accounts only; run variables are audited as name
and value; a world-writable inbox switches the channel off; the engine
lock belongs to the headless artifact only; the setup GUI may be bound to
loopback, with a Host/Origin filter.

Still open, neither changes the design: Q6 (CLI client copied beside
Tomcat) and Q7 (is a browser available on the server).
