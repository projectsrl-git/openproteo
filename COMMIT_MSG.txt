CLAUDE.md: overlapping rules in a spec must decide their intersection

A contract amendment, no code.

Twice in the same executor, in the same month, a spec that said two
things produced code that followed the worse half:

- objpack's objectSource default. The prose said "order is not the
  default", the parameter table said it was. The code followed the table:
  seven wrong row/object pairings out of seven on a real feed, stopped only
  by chance by a mime-type check. Had every object shared an extension,
  seven documents would have been archived under a neighbour's metadata.
- objpack's object_id. "An unmapped role falls back to the Transarch name"
  against "an unmapped object_id means assign 1..N". The code followed the
  first, and the row-discard option was unusable on every real metadata
  CSV, all of which carry an object_id column. The PowerShell script being
  replaced stated the answer plainly ("Se object_id e' presente nel
  sorgente lo ignoriamo"); the spec had not carried it over.

Added under "Principi non negoziabili", directly after Spec-first so it
sits in the part of the contract that is always read in full: when two
statements in a spec can apply to the same case, the spec names which one
wins on that case, with an example - next to BOTH statements; prose and
parameter table agree on defaults and change together; a reference
contract's behaviour on the intersection is quoted; a contradiction found
later is corrected where it originated, struck through.

And a corollary from the same incident: a test must present a case the way
production presents it. The guard for "discarding under a mapped object_id"
tested the map.objectId parameter; in production the id arrived through the
column name, the parameter was empty, and the guard never fired. Its test
used an explicit mapping, and no test in the suite had an unmapped
object_id column - the shape of every real file. The mutation that removes
a guard must fail its test, and the failure must distinguish the new
message from the old one rather than match a phrase they share.

Pre-commit checklist item 8 points back to the principle, so it is checked
at the moment of delivery and not only remembered.

While reading the contract for this, two checks from "Verifica prima della
consegna" turned out never to have been run on the designer changes made
across the objpack and csvsql batches: no literal \n or \r inside inline
<script> (the UBS proxy rewrites them), and no [[ / [( outside Thymeleaf
comments. node --check had been run every time and catches neither. Both
were run now on designer.html at 4af270a: zero occurrences of each. The
scanner was first shown to find a planted \n and a stray [[ while allowing
the /*[[...]]*/ form, so the zero is a real result.

Applies cleanly on 4af270a both before and after the pending object_id
patch; the two touch different regions of CLAUDE.md.
