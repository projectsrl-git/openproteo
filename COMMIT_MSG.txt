objunpack: say what it is doing while it runs

On the first real run (Windows, a 293 MB package) the live console
showed "checksum verified" and then nothing for minutes: the step
logged nothing between the checksum and the end of the extraction, so
working and hung looked the same.

Now each phase logs a line when it starts, and the two long ones log a
heartbeat every 5 seconds: members read with megabytes and percentage
of the archive file (also from inside one large member), then files
named. Nothing else changes - same output, variables and exit codes,
no parameter.

objpack had this defect and this fix on 2026-09-29; it was not carried
into the new executor and no test asserted it. Now one does.

USAGE.md: "While it runs", including why many small objects are slow
by their number. README.md and CLAUDE.md not touched.

Verified on Linux (sandbox; Temurin 1.8.0_432 and JDK 21.0.10 both
run; root and uid 65534; LANG=C.UTF-8 and empty): core suite in the
eight combinations, 656 assertions, 17 new; 9 mutations of the new
code, all caught; executor and panel suites re-run; 20 000 objects in
a 301 MB tar unpacked in under 5 s, so nothing grows faster than the
object count; git apply --check on a second clean clone.
Verified on Windows: nothing by me; the author's run there found the
defect and shows the step starts and verifies the checksum.
Not verified on either: how long the author's package takes on his
host; mvn clean package.
