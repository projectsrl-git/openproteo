json2csv batch 3: the mapper, and a panel that is run rather than inspected

104 assertions green in two new suites - 56 on the path catalogue, 48 on the
panel - on top of the 267 from batches 1 and 2. Eight further mutations, all
caught.

This feed is Transarch and not ELAR. Corrected in the specification and in
MappingValidator; the executor is unaffected.

THREE ANSWERS CLOSED WITHOUT TOUCHING CODE

RFC-4180 quoting is what CsvWriter already does, so a value carrying the
delimiter is already handled. ObjectName already writes the file name.
recordBusinessDateFormat is already the output mask. What the real sample
changed is the catalogue, not the executor.

KEYS CONTAIN DOTS

VM.CAP.DATE.CHARGE and VM.ALT.ACCT.TYPE are single keys with dots inside them,
not nesting. Emitted bare, VM.CAP.DATE.CHARGE parses as four nested keys and
resolves to nothing at all - on a path the dropdown itself handed over. The
catalogue emits the quoted form, and the suite asserts both halves: that the
quoted form is produced, and that the bare form parses to four segments and
resolves to nothing.

Arrays in this feed hold exactly one object, so the catalogue lists two things
per array: the unbounded [], shown and disabled with its reason, and the first
element's members under [0], which are selectable. Listing only [] would leave
those values unreachable; offering [0] as though it were the whole array is
the mistake the refusal exists to prevent. This is what the explicit index was
added for at the Gate 0 review.

MAPPING A HUNDRED COLUMNS

The dataschema and the JSON share one vocabulary, so there is a
map-by-exact-name button, and the declared type preselects Number. Both are
suggestions and stay editable. Map-by-name never overwrites a column already
mapped: the ones a person set deliberately are exactly the ones a bulk action
must not touch. Matching is exact and case-sensitive, because JSON keys are,
and because a near-match offered as a match would be accepted without being
read.

Every catalogue entry carries how many of the scanned documents contained it.
Seen in 3 of 20 is not the same as seen in 20 of 20, and only the person
mapping the column can say which is expected. The catalogue is held per node
in the browser and never in the workflow: it is a picture of what some sample
files happened to contain, and persisting it would let a stale snapshot decide
a mapping months later.

THE PANEL IS EXECUTED, NOT INSPECTED

tests/panel.js extracts the json2csv branch from designer.html, wraps it in
the helpers it leans on and runs it to produce real HTML - the same technique
that verified the USAGE.md renderer. It asserts tag balance, that unavailable
paths render disabled rather than hidden, that the counts appear, that a
quoted dotted path round-trips verbatim through the attribute, and that every
handler the panel emits names a function that actually exists.

A regex over the source would not have caught the mutation that matters: an
extra </div>, which is the panel defect recorded in CLAUDE.md where the rest
of a section was silently eaten. Rendering catches it in four assertions.

ONE ASSERTION WAS WRONG AND TWO MUTATIONS LIED

X8 was my mistake and not a defect: it claimed apostrophes in a path must be
escaped inside an attribute. They need not be, since inside a double-quoted
attribute an apostrophe is legal HTML and the value round-trips verbatim. It
is replaced by the assertion that matters, plus a new one proving that a
double quote is escaped, because that one would end the attribute.

Two mutations came back green and neither was a pass. One had a sed that
matched nothing; the other had shell quoting that never applied the edit.
Rewritten in Python with an anchor assertion, both are caught, the first by
seven assertions. A mutation that stays green is a claim about the mutation
before it is a claim about the suite, and the only way to tell is to look.

VERIFIED / NOT VERIFIED

Verified: the json2csv package still compiles with javac --release 8 against
the JDK alone; 203 + 64 + 56 assertions green plus 48 panel assertions
rendered with Node; fourteen mutations caught across the three batches; no
literal backslash-n or backslash-r and no [[ or [( in the added panel JS.

Not verified: mvn clean package; the executor on real files; the panel's fetch
calls, since rendering is exercised and the network is not; the two endpoints
themselves, which are Spring controllers - the logic they wrap is tested, the
wiring is not; and the real dataschema.json, so the exact-match test is a
shape test rather than a data test.
