objunpack: designer panel (batch 3)

objunpack can be chosen and configured in the designer: Package,
Output, Checks and limits - eleven fields, one per parameter the
executor reads. Choosing the executor writes the nine defaults into
the step; archive has none and the output directory defaults to the
step's own. clientValidate checks the archive, the five numbers, the
two option lists and the delimiter. The Variables page offers md5Check
and onInconsistency; preserveMtime is shared with unarchive.

No Java. No new runtime parameter: the eleven of batch 2 are now all
settable from the GUI and apply at the next run (checklist 10). A step
written by hand before this batch is not rewritten when opened.

USAGE.md: the objunpack section describes the panel. README.md and
CLAUDE.md not touched.

Verified on Linux (sandbox; node 22, jsdom): the real designer.html
driven through its own controls, 128 assertions; parameters written by
the panel equal those read by runObjUnpack, eleven each, compared
mechanically with a positive control; 28 mutations on copies, 26
caught, 2 equivalent; node --check on the inline scripts with a
control; zero literal \n \r \t and zero [[ [( in the 71 added template
lines, with a control; USAGE.md through docs.html's render(); git
apply --check on a second clean clone.
Verified on Windows: nothing.
Not verified on either: a real browser, the UBS one in particular;
Thymeleaf rendering; the Variables page; mvn clean package.
