CLAUDE.md: one development contract covering both Claude Code and chat delivery

The contract described only work on the git working copy with Claude Code and stated "no zip", which
directly contradicted how the last months of work were actually delivered: patches packaged as a zip and
applied by scripts/deploy_openproteo_patch.bat. Anyone opening a fresh session from this file was being
pointed at the wrong workflow.

Deploy and commit now describes two modes with the same quality rules and one shared requirement,
COMMIT_MSG.txt. Mode A is Claude Code on the working copy. Mode B is chat delivery: one zip per turn
containing the patch, the commit message and csv-viewer.html in the clear, that file being kept out of
the patch because its size and CRLF handling caused repeated conflicts.

The rules written down for mode B are the ones learned the hard way. Patches must be generated on a
fresh clone of the current main and applied there, because copying files from earlier working trees has
already produced a patch that deleted someone else's line. Every patch is dry-run applied on a second
clean clone before delivery. One patch per change, with the order declared when two of them both append
to the end of CLAUDE.md, since that conflicts. And main moves every turn, so the head has to be re-read
before generating anything.

A verification section makes explicit that the project cannot be compiled in the chat sandbox, since
Maven Central is unreachable from it, and that everything verifiable must therefore be verified and
everything else declared: node --check on extracted inline scripts, no literal backslash-n or
backslash-r in JavaScript because the corporate proxy rewrites them, no unsafe Thymeleaf brackets, brace
balance with a counter that ignores strings and comments, an import check after a missing LinkedHashMap
cost a broken build, pom.xml validated with a real XML parser, and isolated logic actually compiled and
executed with javac.

Finally the non-negotiable principles are stated once for both modes: conservative defaults so a deploy
never changes production output, spec-first in .claude for anything non-trivial, Italian conversation
with English code and documentation, and stating plainly what was not verified.

No code changes.
