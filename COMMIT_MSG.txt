unarchive: batch 0, the spec and Gate 0, no code

Specification for a new internal executor that extracts the archives in
a directory (zip, tar, tar.gz/tgz, gz), format chosen or detected from
the magic bytes with the extension only compared. bzip2, xz, 7z, rar and
zstd are recognised and refused naming the format. No code: nothing in
the WAR changes.

Spec:  .claude/UNARCHIVE_EXECUTOR.md
Note:  .claude/2026-09-29-unarchive-batch0-spec.md
CLAUDE.md: new section, and the "4 location" rule corrected with a
strikethrough - the code registers an internal executor in 8 places.

Measured in the sandbox (GNU tar 1.35, Info-ZIP 3.0, Python 3.12,
OpenJDK 21 with --release 8), each changing a decision:
- objpack.UstarReader reports @LongLink, PaxHeaders and git's
  pax_global_header as members, ignores the ustar prefix field (a nested
  file comes back at the root, no error) and returns an empty list with
  no error for a small gzip renamed .tar. Fine for objpack, disqualifying
  for extraction; left untouched.
- Info-ZIP writes UTF-8 names without flag bit 11 and without 0x7075; a
  real CP437 name makes new ZipFile(f) refuse the archive and
  ZipInputStream throw IllegalArgumentException.
- ZipFile does not verify CRC-32; ZipInputStream does but refuses STORED
  entries with a data descriptor. Java 8 ZipEntry exposes no external
  attributes, so a zip -y symlink reads as a regular file.
- GNU tar extracts a tar with no end-of-archive blocks with exit 0.
- Legitimate CSV shapes compress <= 25.5:1; zeros 1028:1.
- id="extract" is already used by three workflow steps in this repo.

Deliberately not in this batch: a USAGE.md section. It would document an
executor the parser still refuses; it is batch 5, rendered through
docs.html's render().

Gate 0: twelve questions; Q1 (name), Q2 (formats), Q3 (who produces the
archives - real samples wanted) block batch 1.

Not verified: anything Windows-specific (reserved names, MAX_PATH, rename
under a scanner) and Java 8 runtime behaviour - the probes ran on JDK 21.
mvn clean package not run and not needed: no source file changes.
