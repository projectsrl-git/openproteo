Mask pools: international streets and cities, and the bare-name rule

Batch 1 of two. Data plus the one line of registration that makes the data
reachable; the "Via " prefix stays a constant and is batch 2.

New src/main/resources/maskdata/streets_international.txt (177 names) and
cities_international.txt (513 cities), both spread over UK, US, DE, FR, ES,
NL and CH. MaskPools.BUNDLED goes 15 -> 17.

The two files alone would have done nothing visible. MaskPools.get() finds a
bundled pool on the classpath, but ApiController.poolList() builds the
catalogue from BUNDLED plus whatever sits in the external mask-pools-dir, so
a file bundled in the WAR and absent from BUNDLED is missing from the
designer dropdown on every installation without an external pools directory
- which is the normal installation. That is why a data batch touches a .java.
Nothing else was needed: designer.html already filters the Streets dropdown
on "streets" and the Cities dropdown on "cities"/"caps".

The street pool holds the NAME ONLY - streets_it.txt has Garibaldi, not Via
Garibaldi - because MaskGenerators.address() writes "Via " + street + " " +
num and the type word is a Java constant. The first line of each new file
states that rule and the reason, so the next pool added does not arrive as
"Oakwood Street" and produce "Via Oakwood Street 42" with nothing failing.

UTF-8 without a BOM is correctness here, not style: get() skips a comment by
testing the first character after String.trim(), and trim() does not remove
U+FEFF. With a BOM the header line would be loaded as a masking value.

USAGE.md said streets and cities were freely selectable it/international when
they were not. Rewritten to what is delivered, plus a paragraph saying the
prefix is fixed and the international pool therefore yields "Via Oakwood 42".
CLAUDE.md's mask section was stale in the same way (BUNDLED 15, only the
company pools listed as having a twin) and is corrected in place rather than
appended, so it cannot conflict with another patch at the tail.
