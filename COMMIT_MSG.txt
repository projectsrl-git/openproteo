Linux: the audit's fixes - rename, order, glob case, links (L3)

Step L3: section 5 of .claude/LINUX_AUDIT.md. No runtime parameter.
Under Windows rules every changed function returns what it returned.

platform/HostFiles holds four JDK operations whose result changes with
the host without any error:

- A processed input is never renamed over an older one. File.renameTo
  refuses an existing target on Windows and REPLACES it on Linux; the
  .done of an earlier delivery was lost silently. Now refused on both
  (elarxml, json2csv, ftpsend, elar split).
- filecopy / safecopy / encoding batch take files in name order off
  Windows, where enumeration is in hash order. On Windows the
  enumeration is not touched.
- filecopy / safecopy say in the log when the host matches file names
  case-sensitively, and how many files a pattern left behind for case
  alone ("*.csv" does not take DATA.CSV on Linux, exit 0).
- RunStore and WorkflowPorter delete recursively without following
  symbolic links.

Every step logs a WARNING for a parameter that is a Linux path joined
with a backslash; no value is changed.

USAGE.md: "Moving a workflow from Windows to Linux". CLAUDE.md: two
rules, in their sections. README.md not touched.

Found and NOT done: the standalone artifact cannot be given a JDBC
driver JAR. Proposed as L4 in the spec, 9.5; the decision is the
author's.
