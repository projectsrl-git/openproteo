Audit report buttons create and download in one click

The per-run buttons in Run history wrote the report and then showed its path
in an alert, leaving the operator to go and find the file. They now hand it
over directly.

POST /api/runs/{feedId}/{runId}/audit-report takes a download=1 parameter and
returns the report bytes with a Content-Disposition attachment header and an
X-Report-File header carrying the name; the page turns the response into a
blob and clicks a hidden anchor. The report is still written under
_logs/runs/{runId}/ as before, because that is where it belongs as evidence,
and the same bytes come back in the same response. One request rather than
two: a separate GET would have to re-derive the file name and could race with
a re-run producing a different one.

download=1 is opt-in, so the JSON contract is untouched for the Operations
bulk endpoint, which still needs {ok:true} to count how many feeds succeeded.

Errors remain JSON with a 200 status - a 4xx body would be replaced by the IIS
error page, as this deployment has already demonstrated twice - so the client
branches on the content type rather than on the status, and reports the reason
instead of saving an error page to disk under a .docx name.
URL.revokeObjectURL runs on a timer rather than immediately, because revoking
straight away can cancel the download in some browsers.

Verified with jsdom by driving the real handler against stubbed responses, 14
assertions passing. The happy path issues exactly one POST carrying both
download=1 and the requested format, triggers a download named from the server
header, revokes the object URL afterwards and shows no alert. A JSON error is
reported with its reason and saves nothing. A non-2xx proxy response is
reported and saves nothing. A missing X-Report-File header falls back to a
sane name rather than downloading something unnamed. Brace and paren balance
is 0/0 on ApiController, node --check passes on runs.html with zero literal
newline/CR escape sequences.

NOT verified: mvn clean package, and the download itself in the browser -
which is the only thing that settles it. Click the .docx button on a
successful run and check that Word opens what arrives.
