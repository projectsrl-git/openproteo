Fix: ${dataSource} was empty inside the step that owns it

Reported from the field on tf0003819.RECON: the variable showed its value
correctly in OUTPUT DATA but resolved to an empty string inside the sqlreport
query of the same step.

The cause is ordering, not naming. A step OUTPUT only reaches run.vars after
the step has finished, so the step that publishes the datasource cannot see it
while it runs - the same class of problem as assignments inside one setvar
step not being able to refer to each other. OUTPUT DATA is read at the end of
the run, which is why that half looked right.

The datasource is now seeded in WorkflowEngine.executeStep alongside stepId,
stepName and stepDir, that is BEFORE the step's parameters and queries are
resolved. The two mechanisms are complementary and both are kept: the seeding
serves the step itself through the unqualified ${dataSource}, while the step
output serves later steps through ${<stepId>.dataSource} and puts the value in
the audit trail and in the audit report's per-step table.

A step WITHOUT a datasource leaves the value alone rather than clearing it.
Clearing was written first and rejected: it would empty the OUTPUT DATA column
of any workflow whose last step is not a SQL one, and leaving it matches how
every other step output already behaves - last writer wins and the value
persists. So the unqualified ${dataSource} is the last SQL step that ran, and
${<stepId>.dataSource} remains the precise per-step form.

Verified with the REAL VarResolver compiled against a transcription of the
seeding block and of the engine's outVar merge, in the actual order the engine
performs them. Eleven assertions pass: the reported expression resolves during
the step instead of being empty, both spellings work, the other per-step
context is untouched, the namespaced form works for later steps after the
merge, a following step with no datasource does not clear the value so OUTPUT
DATA still shows one, two SQL steps against different systems each see their
own during execution and keep their own qualified value afterwards, a blank
datasource does not overwrite, and an unknown step id still resolves to the
empty string rather than to a neighbour's value. Brace and paren balance is
0/0 on WorkflowEngine.
