Fix: the page said the bulk add/remove was "not available yet"

Reported from the field: the "Remove from N feeds" button could not be found.
The code was on main and correct - the button renders for every
non-conflicting partial step - but the section's introductory text was still
the one written when that section was read-only, and it ended with "Adding a
missing step to the other feeds is a separate action, not available yet."

Two later batches added first the add action and then the remove action, and
neither updated that sentence. The page was therefore telling the operator, in
the very place they would look, that the feature did not exist.

The intro now says what can actually be done and where the buttons are. Two
related pieces of text were stale in the same way and are corrected too: the
empty state now explains that the buttons appear only for a step that some of
the selected feeds have and others do not, so "nothing here" reads as an
explanation rather than as something broken; and the executor-conflict note
now says such a step can be neither added nor removed in bulk, instead of
mentioning only the addition.

No behaviour changes: this is entirely the text that explains the behaviour.

The lesson worth keeping is that when a batch turns a read-only view into an
actionable one, the prose explaining WHY it was read-only is part of the
change rather than decoration, and the section text needs grepping as much as
the handlers do.

Verified: node --check passes on variables.html with zero literal newline/CR
escape sequences and no Thymeleaf inlining markers.

NOT verified: mvn clean package. If the button is still not visible after
this, the remaining explanations are that the selection has no partial step at
all - every id present in every selected feed - or that the step in question
has a different executor across feeds, in which case it is deliberately
read-only and now says so.
