unarchive: batch L2, links, permissions and folder times on Linux

Second and last Linux batch; Windows behaviour unchanged.

On a Linux host: symbolic links are created when they stay inside the
archive's folder - checked as text per link, then resolved through the
archive's other links before the commit, so chains and dangling tails
that escape only when followed are refused; nothing is ever written
through a link. Hard links only to a regular file extracted earlier from
the same archive. Permission bits restored as GNU tar and unzip do as a
non-root user (tar minus the umask, zip as stored), never setuid,
setgid, sticky or owner. Folder modes and times applied after their
content. Cleanup gives the owner rwx back before deleting a folder, since
a read-only folder made rm -rf fail for a non-root user (measured).

Verified: links suite 77 (identical to GNU tar and unzip in types, link
targets, content, modes, times and hard-link inodes; 12 hostile fixtures
refused); a program run as a non-root user 6/6 with a positive control;
Windows suites unchanged (232 + 194); Linux 140; wiring 90; panel 114;
guide 45; 17 mutations caught.

server deployment.
