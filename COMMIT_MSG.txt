Headless H2: the instance with no web server, and the loopback GUI

java -jar openproteo-headless.war now runs the headless instance
(.claude/HEADLESS.md, section 14): engine, cron and control channel,
WebApplicationType.NONE, no servlet API in the artifact, no port opened.
The only way in is to log on to the server and use the command line.

- HeadlessConfig (outside the package the GUI artifacts scan) loads the
  same beans minus @Controller/@ControllerAdvice, the web package and
  OrchestratorApplication.
- Before any bean exists: the engine lock .openproteo-engine.lock in the
  workflows directory (headless only, Q10) and the control directory
  checks; either failure refuses the start, exit 1, nothing written.
  After the start, a channel that is not serving also stops it.
- serverAddress, saved from the Platform page into
  openproteo-instance.json, becomes server.address at the next start
  of the standalone; an address that is not the server's own is refused
  when saved. "No effect" is shown under an external Tomcat.
- Loopback guard (Q11): registered only when server.address is set,
  enabled only when it is a loopback address, acting only on requests
  received on loopback. Refuses a foreign Host (DNS rebinding) and a
  change whose Origin/Referer is another site; a request with neither
  passes. Fixed 403 text; the reason goes to the log.
- USAGE.md: the headless instance, setup-to-production procedure, the
  loopback GUI and its limits. CLAUDE.md: artifact description, layout.

No new file-only key: serverAddress is set from the Platform page and
applies at restart.

Verified on Linux: nothing (no Linux machine reachable).
Verified on Windows: Windows 11, Zulu OpenJDK 1.8.0_362, artifacts from
mvn clean package: headless instance with no TCP/UDP socket (standalone
as positive control); runs and approvals through it; four refused
starts leaving nothing on disk; archive without Tomcat/servlet classes;
mutation of the scan exclusions fails the start; loopback bind and
off-host refusal; guard on real requests (403, no run created) and the
pages working through it in the browser; rules harness with two
mutations. Details in section 14.3.
Not verified on either: Linux; a clean stop (processes were killed);
a Windows service or systemd; the guard under an external Tomcat; an
IPv6 loopback bind.
