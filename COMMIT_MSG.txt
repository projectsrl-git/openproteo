Cache-bust the static assets with the build id

Three deploys in a row appeared to change nothing because the browser kept serving a cached
app.css, viewer.js or theme.js: the WAR was new, the assets were not. Static URLs now carry a
per-build token, so a new build is a new URL and the browser refetches on its own.

config/BuildInfo becomes the single source of the build identity: it loads the filtered
build-info.properties once, blanks placeholders an unfiltered build left behind, and exposes map()
(version, buildNumber, commit, shortCommit, buildTime, display, label) together with id(), the short
token used on asset URLs. ApiController.buildInfo() now delegates to it, so /api/version and /api/env
behave exactly as before and only one implementation remains.

web/BuildIdAdvice, a @ControllerAdvice scoped to PageController -- which renders all sixteen
templates -- publishes ${buildId}; the API is a @RestController and is deliberately left out. Every
CSS and JS include in the templates became @{/css/app.css(v=${buildId})} and friends, fifty-four
includes across sixteen templates. Images were left alone: they rarely change and are also referenced
from JS. docs.html fetches USAGE.md from JavaScript, so it receives the same token through a
<meta name="op-build" th:content="${buildId}"> tag read by the script, which avoids inlining Thymeleaf
inside JS.

id() is <buildNumber>-<shortCommit>, for example 73-ed576c9. On a build made without those properties
it falls back to the digits of the build time, and finally to a per-JVM token so that even a
development restart refreshes the assets.

Docs: .claude/2026-08-02-static-cache-busting.md and CLAUDE.md.

Verify: BuildInfo was compiled and executed in the three real scenarios -- a full script build
(73-ed576c9), a plain mvn package (falls back to the timestamp) and a completely unfiltered build
(still a usable token, with the version badge correctly hidden). All sixteen templates pass
node --check with no literal \n or \r and no unsafe Thymeleaf, and ApiController's brace balance is
unchanged. Java not compiled as a whole in the chat sandbox -- run the Maven build on deploy.
