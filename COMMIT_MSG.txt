Mask address prefix: Gate 0 answered, option B chosen, still no code

Revision A of .claude/MASK_ADDRESS_PREFIX.md. The recommendation in that
spec was NOT adopted: the type word goes into the pool values and there is
no new parameter at all, as the original executor behaved. The author picks
a street file from the existing dropdown and decides nothing else.

The rejected analysis is left standing with strikethrough rather than
rewritten. Sections 4 and 5 are marked superseded and section 10 carries the
decision; a decision only reads as one beside what it overruled.

Gate 0: 1 no parameter, no template; 2 and 3 moot; 4 the international pool
is UNUSABLE until this ships, so batch 2 is what makes batch 1 useful; 5 per
step, never per column.

Recorded in B's favour, because the earlier analysis undersold it: the
prefix-position objection that ruled out a bare parameter DISAPPEARS under
B. The word order lives in the value, so choosing the file chooses the order
too - which a template could only reach by having someone type the right one
per feed.

The objection against B is NOT withdrawn, and it cannot be validated away.
Nothing in a value can tell the executor whether a type word is present:
Damrak is a complete Dutch street name and Garibaldi is not a street name at
all, and no rule separates them. A heuristic would fire on the legitimate
Dutch entries and pass the broken Italian ones. The answer is visibility
rather than a guard: the step log prints the street pool in effect with its
size and first value, always, including at the default.

TWO THINGS THE DECISION PULLS IN, BOTH FOUND BY READING
- MaskGenerators:88 has "Roma" as the fallback for an EMPTY pool. With the
  constant removed that path yields "Roma 47" instead of "Via Roma 47", so
  the fallback becomes "Via Roma". One word, in a branch nothing normally
  reaches, which is why it would have survived a review of the diff.
- Byte-identity holds only if every one of the 60 lines of streets_it.txt
  gains "Via ". One line missed changes that value's output for every
  customer who draws it and nothing fails, so the migration is verified by
  digest over the whole pool, never by reading the file.

Batch 1's own artefacts invert one commit later: both file headers, the
USAGE.md paragraph and the CLAUDE.md lines it added. That is part of the
change, not decoration - the stale-text defect on record was a feature
landing while the prose still described the old behaviour.

VERIFIED

  German strasse with an eszett (0xDF in both) can be used, and a masked
  value still survives a Latin-1 sink downstream.

OPEN, AND IT CANNOT WAIT (section 10.9)
streets_international.txt is ONE file mixing seven countries, so a single
delivery would carry Oakwood Street, Rue Voltaire and Bahnhofstrasse in the
same column. The alternative is one file per country, so the dropdown
selects a language as well as a set of names. Recommended: split. It must be
decided BEFORE first use, because changing a pool moves the address of
nearly every customer already delivered - 1962 of 2000 for a single added
line - and answer 4 says the pool has never run, so this is the one moment
the layout is free.
