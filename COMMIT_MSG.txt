Headless H3a: move the loopback GUI from main to feature/loopback-gui

The RHEL8 scenario (.claude/HEADLESS.md section 15) runs only the
headless instance on the server, so the loopback GUI of H2 (bind address
serverAddress and the Host/Origin guard) is not used. Decision D1: keep
it on the branch feature/loopback-gui (at 20a9198, pushed) and remove it
from main with a forward commit; history is not rewritten.

- Removed web/LoopbackRules and web/LoopbackGuard; the serverAddress
  mapping, constant and status fields.
- ControlController and platform.html back to their H1 version (only
  H2 had touched them since).
- USAGE.md: "The GUI only from the server" removed. Spec: notes at Q7,
  Q11 and section 14, delivery in section 15.15.
- A saved serverAddress is not rewritten (Default conservativi): it is
  ignored.

Verified on Linux: nothing (no Linux machine reachable).
Verified on Windows: Zulu OpenJDK 1.8.0_362, Maven artifacts: a
standalone with a saved serverAddress 127.0.0.1 binds every interface
and accepts a foreign Host; the file is not rewritten; the headless
artifact still starts, lists feeds and stops; template scans clean.
Not verified on either: nothing specific to this change beyond that.
