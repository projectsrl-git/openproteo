Windows process-tree kill: experimental, off by default (W)

Step W. NOT RUN ON WINDOWS. Off unless
orchestrator.windows-tree-kill=true; with it off a Windows instance
does exactly what it did, and the suite asserts that nothing
Windows-specific is called.

engine/WindowsTreeKill: on timeout and Stop, kill what the step started
with taskkill /T. Java 8 holds a HANDLE, not a pid, so the step is
found among the JVM's own children (one PowerShell CIM query) by the
moment it was started and by its command line. Exactly one candidate or
nothing: not found, or two steps that cannot be told apart, and only
the interpreter is killed, as before, with the reason in the step log.
Never the JVM, never a system pid. On Java 9+ Process.pid() is used.

ProcessTree gains a TASKKILL mode, live only on Windows with the switch
on; the Platform page shows it as "partial". USAGE.md describes the
option and says plainly that it has not been run on Windows.
