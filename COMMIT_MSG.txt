Fix the missing commit in the version badge, add an automatic progressive, a startup splash and the new claim

1) The commit never appeared because spring-boot-starter-parent 2.7.x sets resource.delimiter to @ and
configures maven-resources-plugin with useDefaultDelimiters=false (verified in the spring-boot sources
for v2.7.18). In a filtered resource only @token@ is substituted, so @project.version@ worked while
${git.commit} and ${maven.build.timestamp} were written out verbatim and the endpoint correctly blanked
them. build-info.properties now uses @...@ for every placeholder.

2) Automatic progressive: build.number is the commit count (git rev-list --count HEAD) — monotonic,
automatic, with no state file and no new Maven plugin. The deploy .bat passes -Dbuild.number together
with -Dgit.commit on the post-commit rebuild, so the WAR carries both. The badge now reads
v<version>.<build> · <commit> (e.g. v1.0.0.148 · 32a1a78) with version, build, commit and build time in
the tooltip. buildInfo() gained a build-time fallback to the last-modified of build-info.properties and
keeps blanking unfiltered placeholders, so a plain mvn package still shows the version.

3) Startup splash: theme.js mountSplash() shows a full-screen splash (logo, wordmark, claim, version)
the first time a browser-tab session opens the app, guarded by sessionStorage. It fades itself out after
two seconds, closes on any click or key press and has a six-second hard safety net so it can never trap
the UI; it honours prefers-reduced-motion and is skipped if storage is blocked. Styles in app.css with a
light-theme variant.

4) The dashboard topbar claim is now "Pipeline Workflow Orchestrator" instead of "Legal Archive · feed
preparation & delivery", and the opening line of USAGE.md was aligned.

Docs: .claude/2026-07-28-version-progressive-splash-claim.md and CLAUDE.md.

Verify: buildInfo() was compiled and executed in three scenarios — filtered (label 1.0.0.148 · 32a1a78),
plain build (version only, build time from the file mtime) and fully unfiltered (all blank, badge
hidden). pom.xml was validated with an XML parser: well-formed, a single <properties> block and no double
dash inside comments, which is what broke the previous attempt. theme.js passes node --check with zero
literal \n or \r. Java not compiled as a whole in the chat sandbox -- run the Maven build on deploy.
