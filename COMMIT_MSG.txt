Headless H3b: console, start and shutdown for the RHEL8 scenario

The author's scenario (.claude/HEADLESS.md section 15): no HTTP on the
server, people reach OpenProteo only by SSH, one instance started from
the shell, then a console inside the program.

- openproteo start: starts the headless instance in the background from
  OPENPROTEO_HOME (setsid on Linux, output to logs/console.out), refuses
  when an instance already serves (exit 12), waits for its heartbeat and
  prints a refused start's reason.
- openproteo connect: interactive console. help, feeds, use, runs,
  status, log, run name=value, follow, approve, reject, resume, stop,
  reload, audit-verify, ping, exit, shutdown. "last" and list numbers
  for runs and feeds. run/approve/reject/resume follow the run with its
  step logs; Ctrl-C returns to the prompt (sun.misc.Signal).
- shutdown: headless only, refused with QUEUED/RUNNING runs unless
  --force, INSTANCE_SHUTDOWN audited in every feed, then a clean stop
  (heartbeat stopped, lock released, exit 0). One-shot form for scripts.
- Inbox polled every 250 ms. Wrappers default OPENPROTEO_HOME to their
  own folder. tools/openproteo.service systemd template.
- Spec: Q12 (no import), Q14 confirmed, rlwrap is in EPEL,
  KillUserProcesses=yes needs the systemd unit; H3a (loopback GUI to a
  branch) moved after the demo. USAGE: install, start, connect.

No new runtime key: OPENPROTEO_HOME and OPENPROTEO_JAVA_OPTS are
installation environment.

Verified on Linux: nothing yet (first run: the demo on a Linux server).
Verified on Windows: Windows 11, Zulu OpenJDK 1.8.0_362, Maven
artifacts: start and refused second start; a scripted console session
through run, gate, approve, logs, errors and exit; shutdown refused with
a running run, then forced, with a clean stop (stopped flag, process
gone, audited, chains verifying after restart); one-shot shutdown.
Not verified on either: setsid and surviving SSH logout; Ctrl-C while
following (no interactive terminal); the systemd unit; start under
sudo; two operators.
