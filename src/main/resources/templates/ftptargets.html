FTPS targets

Delivery destinations referenced by id from ftpsend steps. Explicit TLS on the control channel, passive data connections, authentication by client certificate held in a PKCS#12 file. Passwords are stored in the targets JSON file — protect it with filesystem permissions.

Leave the password empty when the account authenticates by certificate alone. The client then never sends PASS: a 230 arriving straight after USER is a completed login, and pushing a password into it would be answered 503 at best.

There is no configured base directory, so the path is absolute and the target is specific to the machine it was written on: exported to another environment it carries a path that must be rewritten. The step checks the file exists and is readable before opening any socket, so a wrong path says so instead of surfacing as a failed TLS handshake.
